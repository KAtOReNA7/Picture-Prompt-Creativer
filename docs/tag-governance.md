# 标签治理说明

阶段 16A 增加标签统计、分类、分级、别名和人工确认合并流程，用于减少 Prompt 库中的近义、重复标签。

## 标签分类

允许分类：

- 风格
- 题材
- 场景
- 色彩
- 光影
- 构图
- 情绪
- 用途
- 平台
- 质量
- 其他

未设置分类的标签会显示为“未分类”。

## 标签等级

- 等级 1：大类标签，例如“电影感”“封面图”“悬疑”。
- 等级 2：细分标签，例如“冷色电影感”“雨夜悬疑”。
- 等级 3：具体风格或项目标签，例如“蓝绿色强对比悬疑封面”。

## 标签合并逻辑

标签合并必须由用户人工确认，AI 只提供建议。

合并时会：

- 创建或更新目标标签。
- 将 source tags 关联的 `PromptAnalysisTag` 迁移到目标标签。
- 避免重复绑定。
- 将 source tags 标记为 `isArchived=true`。
- 设置 `mergedIntoId` 指向目标标签。
- 为目标标签创建 `TagAlias`，记录 source tag 的原始名称和规范名。

合并不会删除：

- `PromptAnalysis`
- 原始图片
- 生成图片
- 本地文件

## TagAlias 用途

`TagAlias` 用于保留历史别名，方便后续识别近义标签。例如“冷色调电影”“蓝绿色电影感”合并到“冷色电影感”后，原名称会作为别名保存。

## 为什么 AI 只建议不自动合并

标签语义和运营用途有关，AI 可能误判近义关系。比如“冷色电影感”和“悬疑冷色封面”可能相似，但一个偏风格，一个偏用途。为了避免误合并，系统只展示建议，由用户确认后执行。

## 自动治理未分类标签

当未分类标签数量过多时，可以在 `/tags` 使用“AI 自动治理未分类标签”。

自动治理只处理：

- `isArchived=false`
- `category` 为空或未设置

自动治理会：

- 将未分类标签归并为最多 50 个目标标签。
- 自动为目标标签设置分类和等级。
- 将 source tags 的 `PromptAnalysisTag` 关联迁移到目标标签。
- 将旧标签标记为归档，而不是删除。
- 将旧标签名称和历史别名保存到 `TagAlias`。
- 创建 `TagGovernanceRun` 治理记录，保存 AI 计划和执行结果。

自动治理不会：

- 删除 PromptAnalysis。
- 删除原始图片。
- 删除生成图片。
- 删除旧 Tag。
- 处理已分类标签。

自动治理前页面会显示一次全局确认。该操作不需要逐条人工确认，因为范围被限制为“未分类标签”，目标是先把低质量、重复、碎片化标签压缩到可管理规模，再由用户人工微调。

建议治理前先到 `/maintenance` 创建备份。

## 治理记录

每次自动治理都会创建 `TagGovernanceRun`，记录：

- 治理模式
- 状态
- 原标签数量
- 目标标签数量
- 归档标签数量
- 迁移关联数量
- AI 原始计划
- 执行结果
- 错误信息

## 从标签定位 Prompt 图片

在 `/tags` 页面点击“查看图片”，会跳转到 `/library?tagId=xxx`，Prompt 库会按该标签筛选相关素材。

`/library` 默认隐藏已归档标签，标签筛选按分类分组，并优先展示使用次数高的标签。

## 常见错误

- 标签分类不在允许列表中：请使用系统提供的 11 个分类之一。
- 标签等级必须是 1-3：请检查输入等级。
- 父级标签不能等于自身：层级关系不能自循环。
- 已归档标签不能快速添加：请到 `/tags` 确认是否已有同类标签。
- AI 建议失败：检查 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_TEXT_MODEL`。
